# Contributing

Thanks for reading *Zen and the Art of Technical Writing* — and for caring
enough to engage with it. This book is being developed in the open. Version
0.5 is the current manuscript, with known structural and mechanical work
ahead on the path to v1.0.

Feedback is welcome, and GitHub's tools make it easy to contribute.

## Ways to contribute

### File an issue

If you spot a typo, have a suggestion, or want to ask a question, open an
issue. There are three templates to choose from:

- **Typo or error** — for mechanical issues (typos, broken links, factual
  errors)
- **Suggestion** — for structural or content feedback
- **Question** — for engagement with the ideas themselves

Pick the one that fits. If you're not sure, use Suggestion.

### Submit a pull request

If you're comfortable with git and GitHub, you can fix things directly:

1. Fork the repo
2. Make your change in a branch
3. Open a pull request against `main`

Every page of the published book has a "Suggest an edit" icon in the top
right — clicking it opens a GitHub editor on the exact file for that
chapter. This is the fastest path for small fixes.

## What kind of feedback is most useful right now

The book is at v0.5, which means the manuscript is complete but not yet
polished. The most valuable feedback right now is:

- **Typos and mechanical errors.** These are easy to fix and genuinely
  helpful.
- **Chapters that don't land.** If a chapter is confusing, unconvincing, or
  doesn't connect to the rest of the book, I want to know.
- **Missing stories.** The framework chapters (roughly Chapters 6–11) are
  being revised to include more anecdotes. If you have a story that
  illustrates one of the six quality characteristics, I'd love to hear it.

Less useful right now:

- **Deep structural overhauls.** The overall structure is largely settled.
  I'll consider big changes for a future edition.
- **Style preferences.** I have strong opinions about voice, and I'd rather
  defend my choices than relitigate them. But if something reads as a
  genuine error in craft (not just a different preference), say so.

## A note on scope

This is a book about quality in technical writing. Issues about the book's
topic are welcome. Issues about the website, the build process, or the
docs-as-code setup are also welcome, but secondary.

## Code of conduct

Be kind. Assume good faith. Disagree with ideas, not people.

Thanks for being here.

— Dave
